A1瀑布流布局:竖图/横图不再被统一裁剪P0M▶

现状

网格用 SliverGrid + childAspectRatio: 100/previewHeight,所有卡片同一宽高比,竖图被裁成方块、横图上下留黑边。而 flutter_staggered_grid_view 已经写进了 pubspec.yaml 却从未 import(全库 grep 无引用)——等于装了没用。

建议

  • 用 MasonryGridView(该包提供)替换 SliverGrid,按 post.sample.width/height 计算每张卡片高度;
  • 在「预览与网格设置」里加一个开关:瀑布流 / 等高网格 两种模式,保留现有用户习惯;
  • e621 API 每个 post 都带原始宽高,不需要等图片加载完就能排版,不会跳动。

改动位置

lib/features/home/views/home_screen.dart(SliverGrid 段)· lib/features/home/widgets/post_card.dart · settings_provider.dart(加布局模式字段)

A2卡片信息层:评级色条 + 类型徽标 + 分数P0S▶

现状

卡片只有一张裸图。用户在点进去之前无法知道:这是不是视频/GIF、分数高低、评级是 Safe 还是 Explicit——对这类内容浏览器 App 来说,评级可见性几乎是刚需。

建议

  • 卡片左缘 3px 色条表示 rating:s 绿 / q 黄 / e 红(e621 官网同款心智);
  • 左下角小徽标:▶ WEBM / GIF(post.file.ext 已有);
  • 右下角 ↑ score,超过千用 1.2k;
  • 全部叠加在图片上,用渐变底保证可读,不增加卡片高度。

改动位置

lib/features/home/widgets/post_card.dart(模型 e621_post.dart 里 score/rating/file.ext 字段都已存在,纯 UI 工作)

A3无限滚动模式(与分页并存,可切换)P1M▶

现状

翻页靠底部 ◀ Page n ▶ 按钮,每次整页替换 posts,翻页后滚动位置回顶。移动端主流浏览体验是无限滚动。

建议

  • 设置里加「浏览模式:无限滚动 / 分页」。无限滚动用 ScrollController 距底 800px 时追加下一页(state.posts 改为累加而非替换);
  • 保留分页模式给"想直接跳到第 500 页"的重度用户——你已经做了跳页对话框,这是差异化优点,别删;
  • 顺手修:跳页对话框里 TextEditingController 建在 builder 里没有 dispose(内存泄漏,上次清单第 8 项)。
